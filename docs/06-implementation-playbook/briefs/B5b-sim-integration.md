## Deliverables
1. **CustomerAgent executor** — turns B5a `CustomerPlan`s into real calls on `app.facade`: OTP signup via `SmsSim`, optional KYC, quote, order, payment with method-faithful world mechanics (gateway: `gateway.simulateCustomerPayment`; c2c: `bank.injectCustomerTransfer` at the exact unique amount + receipt submission with planned mistakes: wrong amount, late, duplicate, abandon; USDT: `chain.injectIncoming` incl. under/over-pay, wrong network; wallet), waiting behaviour (patience, nudges, tickets), confirm/reveal/dispute, repeat/referral/churn feedback into `Reputation`/`RetentionModel`. Fraud plans stress the real risk rules; losses appear only through real app flows.
2. **OperatorPool** — staff entities (`data/sim/staff.json`) pulling from the **real operator queue** via `app.facade.admin` (claim → virtual-time work by task kind/skill → complete/fail), using `ProviderPanel` for panel-mode providers; shifts (IRST), overtime for rush, errors → rework/refund, utilisation stats, hire/fire API for the owner. **SupportDesk** — tickets from delays/failures; capacity & resolution quality.
3. **Accountant** — month-end (Jalali boundaries) statements from the app ledger via `app.services.ledger/reports`; identity checks (A = L + E; Σ entries = 0; USDT conservation vs port balances; revenue = Σ delivered revenue; order unit economics vs ledger); nominal/real/USD views; `ledgerHash()`; break-even date, runway, ROI, max drawdown, payback; digest builder glue.
4. **Runner** — `runSimulation(opts)`: creates SimClock/world/app (`createApp` with `world.ports()`, mode `sim`, `:memory:` DB or file), wires agents, demand buckets, owner policy/decisions file, job ticking cadence (sim-spec §1), progress callbacks, `--until`, checkpoint digests, deterministic replay, performance work (batch transactions per tick, quote caching, minimal allocations; target ≥ 300 orders/s, 3 years < 10 min at ~150 orders/day, < 2 GB). `createDemoSim(app, world, runner?)` for API demo mode (`/sim/*`: advance minutes, speed, scenario switch, event injection, `SimStateDto`), with the same agents running live at the chosen speed.
5. **CLI** — exactly as `sim-spec.md` §4 (`sim`, `sim:suite`, `sim:compare`, `sim:sensitivity`) writing `reports/<run>/` per §5; `npm run sim -- --help` documents flags.
6. **Integration tests** — 30-day base run < 60 s with identity checks; determinism (two runs ⇒ same ledger hash; different seeds differ); all 15 scenarios run 60 days without invariant violations; behavioural assertions: devaluation shock → quotes rise within buffer window and conversion drops; gateway blackout shifts payment mix; provider freeze → failover/refunds; night halt + caps constrain buys; deposit-cap scenario reduces sustainable GMV; fraud segment losses bounded; operator shortage lengthens SLA; owner decisions file changes margin on the stated date.
7. **First real runs** — execute `base` for **3 simulated years** (seed 1) and write the full report folder; record runtime/throughput; then run the **15-scenario suite** (1 seed, 3 years if time allows else 18 months) and the sensitivity sweep; commit-ready outputs in `reports/`. Triage anomalies (negative equity without cause, impossible margins, stuck orders): find root cause in the engine/world (fix or report precisely) — do **not** tune parameters to hide defects.

## Return
Files, CLI usage, throughput/runtime, **headline numbers of the 3-year base run** (revenue, gross/net profit, cash, break-even date, ROI), suite summary table, defects found/fixed (by package), assumptions & parameter sources, open issues.
