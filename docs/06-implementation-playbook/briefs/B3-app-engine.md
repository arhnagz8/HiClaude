## Services to build (each = class + tests; all state in SQLite; all time via `Clock`; all ports via `deps.ports`)

1. **LedgerService** — `post(entryInput)` transactional (validates via `core.LedgerBook` rules: Σirt=0, currency rules, no negative USDT), persists entries/lines, publishes `ledger.posted`; typed helpers for every template E1–E18 (calls `core/ledger/templates`, pulls book cost for USDT disposals from stored balances); `balance(account)`, `trialBalance()`, `movements(range)`, `revalueUsdt(now, mid)` (E11); **statements**: `incomeStatement(period)`, `balanceSheet(asOf)`, `cashFlow(period)`, `statements(period)` using core builders; `realTerms/usdTerms`; invariants check method `assertIntegrity()` (Σ all lines = 0; per-account qty/irt roll-ups; A = L + E).
2. **RateService** — `refresh()` (poll all enabled `ExchangeAccountPort.ticker/limits`, `aggregateRates`, volatility estimator state persisted/rebuilt from `rate_snapshots`, store snapshot, kill-switch evaluation with auto-on/off + manual switch persisted in `kill_switches`, publish `rates.updated`/`killswitch.changed`), `current()` (throws `RATES_UNAVAILABLE`/`KILL_SWITCH` when unusable), `history(hours)`, `rateBoard()` for the public config (our indicative USD sell rate = pricing of a typical $100 top-up ÷ 100), `change24h`.
3. **PricingService** — `quote(request, customer?)`: validates product/amount/inputs/rush tier, loads policy (versioned) + rate + competitor reference (via `ports.competitors` when enabled; cache) + customer tier + rush capacity (core/sla) → `core.priceQuote` → persists `Quote` (internal fields kept) → returns Quote + public `QuoteDto` mapper (never leaks cost/margin). `fromPrice(product)` cached per rate snapshot for catalog "from" prices. `whatIf(productId, amount, policyPatch)` for admin. `listQuotesStats`. Quote expiry handling.
4. **OrderService** — `createOrder({quoteId, method, network?, inputs, channel, idempotencyKey, customer})` with all guards (quote valid & unexpired, customer risk via `core.assessOrder`, method availability/limits, idempotency, rush capacity re-check) → creates order + payment intent (delegates to PaymentService) + `awaiting_payment`; `apply(orderId, event, actor)` runs `core.transition`, executes returned effects (ledger posts, task creation, notifications, timers), appends `order_events`, bumps `version` (optimistic lock → `CONFLICT`), publishes events; customer actions (cancel/confirm/dispute), operator actions (approve/reject payment, hold/release, retry, cancel, refund); `refund(orderId, mode)` (wallet/bank) with ledger E12 and refund fee policy; `toDto(order, viewer)` (customer + admin variants with `canX` flags, timeline labels in Persian, ETA via `core/sla`); timers via the job `orders.expire`.
5. **PaymentService** — per method:
   * **gateway**: `create` via `PaymentGatewayPort` (amount in Toman→Rial at the adapter boundary only), callback handling `verify` (amount/status match; mismatch ⇒ alert + review), settlement job (E1b) respecting `gatewaySettlementAt`.
   * **card_to_card**: destination card selection (least-loaded under per-card daily cap), unique amount via `core.makeUniqueAmount`, receipt submission (tracking no, last4, image ref stored on disk/db blob), `payments.poll` job pulls `BankPort.listCredits(since)` → `core.matchBankCredits` → auto-confirm exact matches; ambiguous/unmatched go to the admin "unmatched" queue; duplicate protection; under/over-pay handling (overpay → wallet credit, E17).
   * **bank_transfer**: reference code + statement matching.
   * **usdt**: per-order address via `ChainPort.allocateDepositAddress`, polling `listIncoming`, AML `screenAddress` (blocked ⇒ reject + alert), confirmations per network (params), `core.evaluateUsdtReceipt` (underpaid/overpaid/wrong network), E3 at mid.
   * **wallet**: atomic debit (E4).
   * Late payments via `core.evaluateLatePayment`. Every confirmation publishes `payment.confirmed` and moves the order via OrderService.
6. **FulfilmentService** — on `paid`/`queued`: create `FulfilmentTask`s (kind by product kind; mode by provider capabilities × product mode; instructions in Persian with exact steps/params for operators), **funding check** against provider balance (via TreasuryService; if insufficient set `waitingFunding` and trigger a replenishment plan), API dispatch (`ProviderPort.issueCard/topUpCard/payVendor`, retries with backoff, provider health tracking → `core.providerHealth`), operator queue (`claim/release/complete/fail` with permission checks, SLA due dates by rush tier, priority = tier + age), delivery payload encryption (`crypto.encryptSecret`) + `DeliverySummary`, **reveal** flow (one-time token with TTL, step-up OTP flag, reveal counter, audit), completion → ledger E5 (revenue + COGS from actual funding), `fulfilment.*` events, SLA warnings/breaches (alerts), auto-complete timer, **failure path** → auto refund policy or retry via alternate provider (`altProviderIds`).
7. **TreasuryService** — `sync()` balances from ports into stored state; USDT lots (`core.UsdtLotBook` persisted to `usdt_lots`), `plan()` via `core.planReplenishment` (+ persisted plan items with blocked reasons), `execute(item)` for deposit_irt (bank→exchange via `BankPort.transferOut`/gateway method), buy_usdt (`ExchangeAccountPort.buyUsdt`, E7/E8, lot creation with `withdrawableAt`), withdraw_usdt (E9; then poll `withdrawal()` → E10), sweep_provider (`ChainPort.send` to provider deposit address, `ProviderPort.creditStatus` polling → E6), manual actions from admin, `coverage()`, demand history from delivered orders, daily `revalue` (E11), reconciliation report (ledger vs port balances; differences → alerts), cash reserve checks, per-provider float caps. Handle partial failures idempotently (re-run safe).
8. **ReportService** — `kpis(range)` → `KpiRow[]` (definitions in contracts/reports.ts; computed from orders/ledger/tasks), `dashboard()` → `DashboardDto`, `unitEconomics(orderId)`, `marginByProduct/family/provider/channel` (ledger refs), `cohorts()`, `kpi_daily` snapshot job, statements pass-through.
9. **SupportService** (tickets CRUD, assignment, canned replies, links to orders), **ExpenseService** (`record(kind, amount, memo)`, recurring schedule from settings (salaries, rent, hosting, marketing), E13; monthly **tax accrual** E15 using `params.tax` — VAT payable at delivery (E5) and income tax on positive monthly profit per `entityType`; payment methods; owner draws/capital E14).
10. **Business jobs** — `src/jobs/business.ts` registers: `rates.refresh`, `payments.poll`, `orders.expire`, `fulfilment.dispatch`, `fulfilment.sla`, `treasury.sync`, `treasury.plan`, `ledger.revalue` (00:05 IRST), `gateway.settle`, `expenses.recurring`, `taxes.accrue`, `reports.snapshot`, `risk.scan`, `notifications.retry` with the cadences in architecture §10 (cadence overridable via params for sim speed).
11. **Public façade** — `app.services.*` fully typed (replace the `unknown` slots); `app.facade` with high-level, API-shaped methods used by apps/api **and** the simulator: `publicConfig()`, `catalog()`, `quote()`, `createOrder()`, `getOrder()`, `listOrders()`, `submitReceipt()`, `reveal()`, `me()`, admin methods mirroring `api-spec.md`. The facade is the single place where customer/admin DTOs are produced.
